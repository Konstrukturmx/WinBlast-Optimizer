# WinBlast0 v1.7.0 — Bugs found and fixed during the Slint migration

Each entry names the defect, what the user saw, and the regression test that now covers it.

| # | Area | Defect (v1.6.1 / pre-1.7.0 Slint) | User-visible effect | Fix / regression test |
|---|---|---|---|---|
| 1 | Startup & Tasks | `StartupBatchToggled` / `TasksBatchToggled` handlers never released `startup_tasks_inflight` | After any batch enable/disable the Startup view stayed busy and the "Updating startup services…" HUD never closed until restart | Counter released in both handlers (`src/app.rs`); `startup_batch_disable_selected_entries_in_sandbox` |
| 2 | Advanced Matrix | Risk chips only ran a text search for the English word ("safe", "high"…) | Most tweaks of the chosen risk were not shown | Chips match the tweak's real stability risk (`MatrixQuery`); `matrix_risk_chips_filter_by_real_stability_risk` |
| 3 | Advanced Matrix | Select All / Deselect All used plain lowercase English matching, unlike the list | Searching in another language and pressing Select All selected nothing | Shared `AppState::tweak_matches_query`; `matrix_select_all_respects_the_visible_filter` |
| 4 | Advanced Matrix | "Export Selected" only set a status message | Nothing was exported | Calls `export_profile()` |
| 5 | Advanced Matrix | Hard-coded Turkish/English headings | Mixed-language UI | 4 new catalog keys × 8 languages |
| 6 | Dashboard | Invented fallbacks ("Intel / AMD Processor", "DDR4/DDR5 Memory", 12.5 MB update size) | Fake hardware/update data (AGENTS rule 2) | "Detecting…" / hidden size; `dashboard_never_shows_fabricated_hardware` |
| 7 | Slint shell (pre-1.7.0) | `run_repair_task` set `repair_any_running` and never cleared it; ~80 Slint callbacks unwired; fabricated hardware defaults in .slint | Buttons did nothing; repair stayed "running"; fake CPU/GPU names | Shell + views rewritten on store globals; parity tests |
| 9 | Privacy Shield | "Select All" used a different category test than the list, ignored OS/hardware compatibility and Easy-mode rules, and staged transitions even in Instant mode | Selected tweaks that were not shown or not applicable | `AppState::select_privacy_tweaks`; `privacy_stats_list_and_select_all_are_consistent` |
| 10 | Disk Health | "TRIM All" ran `Optimize-Volume -ReTrim` synchronously on the UI thread and bypassed the backend | Window froze for the whole ReTrim; could not be sandboxed | `SystemBackend::run_trim_all` + `AppState::run_trim_all_async` (HUD shows progress); `disk_view_trim_is_async_and_direct_storage_is_not_claimed` |
| 11 | Disk Health | "DirectStorage supported" was always appended to the TRIM banner | False capability claim | Shown only when `nvme_direct_storage_supported` |
| 12 | Thermal | Missing sensors rendered "0.0°C", "Auto PWM Active", "Smart Fan Curve Active"; GPU throttling hard-coded to "None" | Fabricated telemetry (AGENTS rule 2) | "—" placeholders + OEM banner, real `gpu_throttling_active`; `thermal_view_never_invents_temperatures` |
| 13 | Disk / Thermal | Probes called the hardware directly, not via `SystemBackend` | Sandboxed tests read the host's real sensors and disks | `probe_disk_report` / `read_thermal_snapshot` backend methods (sandbox returns none) |
| 14 | Driver & BIOS | Driver install, sandbox test install and driver backup ran synchronously on the UI thread; the in-flight flag was set and cleared inside the same call | Window froze for the whole download/pnputil run; "Installing…" never appeared; double clicks queued installs | Worker-thread `install_driver_update` / `backup_driver` with `DriverItemUpdated` event, re-entry guard; `drivers_scan_filter_install_and_backup_are_async_and_sandboxed` |
| 15 | Driver & BIOS | Driver scan, BIOS probe, install and backup bypassed `SystemBackend` | Tests would download/install real drivers on the host | `scan_driver_updates` / `probe_bios_info` / `install_driver` / `backup_driver_package` backend methods (sandbox simulates) |
| 16 | Automation Center | Health assessment, memory trim and maintenance-task install/remove ran synchronously on the UI thread, outside `SystemBackend`; the AppState constructor ran a `schtasks` query at startup | UI freezes; slower startup; sandbox could not isolate them | Backend methods + worker threads; maintenance list loaded asynchronously from `setup()`; `automation_profiles_autotune_trim_health_and_maintenance` |
| 17 | Automation Center | The health card asked the user to "run an assessment" but no button existed; maintenance tasks were never shown | Unreachable features | "Assess Health" button and a Scheduled Maintenance section |
| 18 | Goal Planner | Raw untranslated tweak titles in the schedule; ~15 hard-coded English labels | Mixed-language UI | Localized titles + 16 new catalog keys × 8 languages |
| 8 | Clean & Apps / Startup | Hard-coded English ("Select Safe & AI", "Disable/Enable Selected", "All/Active/Inactive", 5 sort labels) | Untranslated UI | 8 new catalog keys × 8 languages |
